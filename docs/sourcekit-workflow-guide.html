Step 1

Open SourceKit and sign in

Do this: Go to getsourcekit.vercel.app and sign in with email or Google using your approved account.

You should see: You should see the current SourceKit auth screen, then land in the recruiter workspace.

Screenshot Target

Chrome window with the SourceKit authentication screen in view.

Area To Frame

The SourceKit logo, sign-in form, and primary CTA with no extra desktop chrome.

Output Path

../output/guide-screenshots/workflow/step-01-sign-in.png

APIs Active In This Step
  • Supabase Auth (session + JWT)
  • No provider search APIs yet
Best Practice

Use one consistent account so saved history and websets are retained.

Step 2

Start in New Search

Do this: Open New Search and set role/company context (example: Staff ML Engineer at Anthropic).

You should see: Role and company fields become the base input for strategy generation.

Screenshot Target

New Search workspace immediately after opening the recruiter dashboard.

Area To Frame

Left navigation plus the Research & Strategy inputs and quick templates.

Output Path

../output/guide-screenshots/workflow/step-02-new-search.png

APIs Active In This Step
  • Front-end state only
  • No external provider call until strategy is launched
Best Practice

Role specificity strongly improves repo targeting and candidate quality.

Step 3

Build sourcing strategy

Do this: Click Build Sourcing Strategy to generate search query, target repos, target companies, and EEA signals.

You should see: You should see strategy progress states and role-specific sourcing logic.

Screenshot Target

Research & Strategy screen while the strategy builder is actively running.

Area To Frame

Progress module, role context, and emerging target-repo / target-company logic.

Output Path

../output/guide-screenshots/workflow/step-03-build-strategy.png

Step 4

Write a target-company and target-repo query

Do this: In Results, use strategy output to compose a query that names target companies and repo ecosystems.

You should see: Your query is visible in the search bar with immediate context on the ranked slate.

Screenshot Target

Results tab with the search bar populated from strategy output.

Query text, visible repo/company anchors, and top of the ranked result list.

Output Path

../output/guide-screenshots/workflow/step-04-query-composition.png

Implementation Notes

  • Exa Answer API: product narrative references grounded answer synthesis, but no direct Exa /answer call is currently wired in this repository.
  • Webset create failures: Failed to fetch states are typically key/quota/connectivity issues in provider path, not just UI issues.
  • Search gating: strategy/search flows enforce auth/subscription gate before expensive provider calls.
  • Webset criteria normalization: server-side webset create path limits criteria to the first five entries.
  • History as completion hub: completed runs (including async paths) are reopened through History for stable results review.
